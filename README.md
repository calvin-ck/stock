# 네이버 주식 시세 조회 앱

종목 코드와 기간(오늘부터 n일 전)을 입력하면 네이버 금융에서 일별 시세를 가져오는 웹 앱입니다.
그리드(등락폭) 매매 전략 백테스트 및 매매일지 확인 기능도 포함되어 있습니다.

배포 주소: https://stock-wgke.onrender.com/

## 구성

- `core.py` — 네이버 금융 스크래핑 + 6개 매매 전략(그리드/이익회수/일별역추세/트레일링역추세/
  고정기준가역추세/자본회수) 계산 로직. **쉘에서 단독 실행/테스트 가능**
- `app.py` — Flask 웹 서버. 6개 전략 × (백테스트 페이지 + 히트맵 페이지) 라우트와 `/`·`/best`를
  담당한다.
- `templates/index.html` — 시세 조회 + 가격 통계 페이지 (`/`, 입력 폼 → 가격 통계(상승/하락
  비율·연속 일수 분포·등락률 분포·갭 분석) → 일별 시세 표/차트, Chart.js)

전략별 백테스트/히트맵 라우트·템플릿·`core.py` 함수는 모두 같은 이름을 쓴다(예: `/grid_trade` →
`grid_trade.html` → `grid_trade_strategy()`, 히트맵도 동일하게 `grid_trade_heatmap` 셋).
6개 전략은 트레일링 그리드 매매(`grid_trade`), 트레일링 이익회수(`profit_recovery`, 매수/매도
없이 `grid_trade_strategy()`의 이익 회수만 사용), 일별 역추세 매매(`daily_reversal`), 트레일링
역추세 매매(`daily_gap`), 고정기준가 역추세 매매(`daily_reference`), 자본 회수
(`capital_recovery`)다.

- `templates/best.html` — 전략별 최고 수익 비교 페이지 (`/best`)
- `templates/best_heatmap.html` — 전략별 × 기간별(180/90/60/30/14/7일) 최고 수익률 히트맵 (`/best_heatmap`)
- `templates/best_sweep_heatmap.html` — 전략별 × 스윕 상한(1,10,...,100%) 최고 수익률 히트맵 (`/best_sweep_heatmap`)
- `templates/_nav.html` — 모든 페이지가 공유하는 상단 네비게이션 partial
- `templates/_csv_file_selector.html` — 종목/종료일/시작일(또는 기간) 선택 UI를 모든 페이지가 공유하는 partial
- `data/` — 종목코드당 CSV 파일 하나(`{code}.csv`)로 시세를 자동 저장하는 폴더 (기본적으로 여기서 읽고, 없거나 부족한 구간만 네이버에서 채움, 최대 2년 보관)
- `requirements.txt` — 의존 패키지

## 설치 및 실행

```bash
pip install -r requirements.txt

# 1) 쉘에서 핵심 라이브러리 단독 테스트
python core.py 005930 --days 30
python core.py 005930 -d 90 --csv samsung.csv

# 2) 쉘에서 그리드 매매 백테스트까지 함께 실행
python core.py 102110 -d 180 --gap 5 --qty 10

# 3) 웹 서버 실행
python app.py
# -> 브라우저에서 http://localhost:8000 접속
```

## 웹 페이지 안내

- **`/` (메인 조회 · 통계)**: 종목 코드 + 종료일/시작일(또는 기간)을 입력해 네이버에서
  시세를 조회합니다. 조회 결과는 자동으로 `data/{code}.csv`에 저장(기존 캐시가 있으면
  병합)되어, 이후 백테스트/히트맵 페이지에서 재사용됩니다. 입력 폼 바로 아래에 매매
  전략과 무관한 가격 통계 — 전날 종가 대비 **상승/하락/보합 일수**와 비율, **연속
  상승·연속 하락(streak) 일수 분포**, 상승일·하락일 각각의 **등락률(%) 분포**(평균·
  최댓값 포함), **당일 갭**(종가−시가)·**전일 갭**(시가−전일종가) 추이 — 를 보여주고,
  맨 아래에 종가 추이 차트와 일별 시세 표(CSV 다운로드, 표 접기/펼치기 포함)를
  보여줍니다. 등락률 히스토그램은 정수(1%p) 단위로 반올림해 집계합니다. 연속 일수별
  1일 평균/합계 등락률 그래프는 왼쪽 y축의 **1일 평균**(항상 표시), 오른쪽 y2축의
  **합계평균**(기본 켜짐)·**합계최대**(기본 꺼짐)를 체크박스로 켜고 끌 수 있습니다
  (자세한 계산은 아래 [가격 통계](#가격-통계-compute_price_stats) 참고).
- **`/grid_trade` (트레일링 그리드 매매)**: 트레일링 고점(max)/저점(min)을 계속 추적하다가,
  거기서 gap%만큼 움직이면 매매하는 백테스트입니다. 자본금 입력은 수익률 계산 기준
  (비우면 시작 자산)으로만 쓰입니다.
- **`/grid_trade_heatmap` (트레일링 그리드 매매 히트맵)**: `/grid_trade` 전용 히트맵으로, 매도gap%
  (매수gap은 비우면 매도gap과 동일) × 매매수량%(둘 다 1~50%, 시작 보유 주식수 대비)
  조합의 수익률과 최종자산을 한 번에 계산해 색상 히트맵으로 보여줍니다. 자본금(비우면
  시작 자산) 필드로 수익률 계산 기준을 바꿀 수 있습니다. 최대/최소 수익률 조합을 큼직한
  카드로 보여주고, **수익률 상위 10 / 하위 10** 조합을 각각 표로 정리해서 보여줍니다.
  히트맵의 각 칸, 상위·하위 10 표의 각 행, 최대/최소 수익률 카드 — 모두 클릭하면 그
  조건 그대로 `/grid_trade` 페이지로 이동합니다.
- **`/profit_recovery` (트레일링 이익회수)**: 그리드 매수/매도는 전혀 하지 않고, 자본금
  (비우면 시작 자산) 대비 평가금액이 이익gap%만큼 벌면 그 시점 평가차익 중 회수율%를
  현금에서 먼저 충당하고 모자라면 주식을 추가로 매도해서 마련한 뒤 별도 적립금으로
  옮기는 백테스트입니다.
- **`/profit_recovery_heatmap` (트레일링 이익회수 히트맵)**: `/profit_recovery` 전용 히트맵으로, 이익gap%
  × 회수율%(둘 다 1~100%) 조합의 수익률을 계산합니다. `/grid_trade_heatmap`과 같은 형태의 카드/표/
  히트맵을 보여주며, 클릭하면 그 조건 그대로 `/profit_recovery` 페이지로 이동합니다.
- **`/daily_reversal` (일별 역추세 매매)**: gap이나 고점/저점 추적 없는 가장 단순한 전략.
  **전날 종가보다 오른 날은 매도, 내린 날은 매수**를 시도합니다 (같으면 매매 없음).
  **매도 수량(%)과 매수 수량(%)을 독립적으로 지정**하며, 둘 다 시작 보유 주식수 대비
  %로 정합니다. "현금 부족해도 매수"를 체크하면 현금 잔고와 무관하게 항상 그대로
  매수하고(현금이 마이너스가 될 수 있음), 체크하지 않으면 쌓인 현금 범위 내에서만
  매수합니다. "시작 자산보다 높을 때만 팔기"(기본 켜짐)를 체크하면 그 시점 평가자산이
  시작 자산을 회복하지 못한 상태에서는 매도하지 않습니다. 매도는 보유 주식수가 모자라면
  건너뜁니다(공매도 없음). 자세한 규칙은 아래
  [일별 역추세 매매 전략](#일별-역추세-매매-전략-daily_reversal_strategy) 참고.
- **`/daily_reversal_heatmap` (일별 역추세 매매 히트맵)**: `/daily_reversal` 전용 히트맵으로, 매도수량%
  1~50% × 매수수량% 1~50%(둘 다 1% 단위, 시작 보유 주식수 대비) 조합의 수익률과 최종자산을
  계산해 색상 히트맵으로 보여줍니다. gap 개념이 없는 전략이라 두 축 모두 수량 비율입니다.
  최대/최소 카드, 상위/하위 10 표, 순위별 수익률 그래프, 전체 순위 목록을 보여주며, 클릭하면
  그 조건 그대로 `/daily_reversal`로 이동합니다.
- **`/daily_gap` (트레일링 역추세 매매)**: 트레일링 고점(max)/저점(min)을 계속 추적하다가,
  **고점에서 gap%만큼 내려가면 매수, 저점에서 gap%만큼 오르면 매도**하는 역추세
  백테스트입니다. max/min은 첫날 종가로 시작해 새 고점/저점을 찍을 때마다 계속
  갱신되고, 매매가 발생하면 그 가격으로 리셋됩니다. 전날 대비 하락한 날에만 매수,
  상승한 날에만 매도해서 하루에 둘 다 발생하지는 않습니다. 매도/매수 수량은 하나의
  값(시작 보유 주식수 대비 %)을 공유합니다. **매도 안 함 / 매수 안 함** 체크박스로
  한쪽 방향만 매매하도록 제한할 수 있습니다.
- **`/daily_gap_heatmap` (트레일링 역추세 매매 히트맵)**: `/daily_gap` 전용 히트맵으로, 등락폭
  gap% × 매매수량%(둘 다 1~50%, 1% 단위, 시작 보유 주식수 대비, 매도/매수 공통) 조합의
  수익률과 최종자산을 계산해 색상 히트맵으로 보여줍니다. 최대/최소 카드, 상위/하위 10
  표, 순위별 수익률 그래프, 전체 순위 목록을 보여주며, 클릭하면 그 조건 그대로
  `/daily_gap`로 이동합니다.
- **`/daily_reference` (고정기준가 역추세 매매)**: 정적인 **기준가** 기준 전략. 기준가는 첫날
  종가로 시작해서 **매매가 일어날 때만** 그 거래가로 갱신되고, 매일 새 고점/저점을
  따라가며 갱신되는 트레일링 방식이 아닙니다. 현재가가 기준가 대비 **상승gap% 이상 오르면
  매도**, **하락gap% 이상 내리면 매수**합니다(하락gap을 비워두면 상승gap과 동일하게 취급).
  매도/매수 수량은 하나의 값(시작 보유 주식수 대비 %)을 공유합니다. **"현금 부족해도
  매수"** 체크박스로 현금 잔고와 무관하게 매수할지(마이너스 현금 허용) 정할 수 있습니다.
  자세한 규칙은 아래
  [고정기준가 역추세 매매 전략](#고정기준가-역추세-매매-전략-daily_reference_strategy) 참고.
- **`/daily_reference_heatmap` (고정기준가 역추세 매매 히트맵, 축 선택형)**: `/daily_reference` 전용 히트맵으로,
  **상승gap · 하락gap · 매도/매수 수량** 3개 중 2개를 X축/Y축으로 직접 골라 스윕합니다.
  축으로 고르지 않은 나머지 하나는 고정값으로 입력합니다. 기본 설정은 X축=상승gap,
  Y축=수량%이고, 이때 고정값인 하락gap을 비워두면 `daily_reference_strategy()`의 기본
  동작과 동일하게 그때그때의 상승gap 값을 그대로 하락gap으로 씁니다("하락gap = 상승gap").
  최대/최소 카드, 상위/하위 10 표, 순위별 수익률 그래프, 전체 순위 목록을 보여주며,
  클릭하면 그 조건 그대로 `/daily_reference`로 이동합니다.
- **`/best` (전략별 최고 수익 비교)**: 6개 전략(트레일링 그리드 매매·트레일링 이익회수·
  일별 역추세 매매·트레일링 역추세 매매·고정기준가 역추세 매매·자본 회수)의 히트맵을
  각각의 기본 스윕 범위와 고정값 그대로 한 번씩 계산해서, 그 안에서 나온 최고 수익률
  조합만 모아 한눈에 비교합니다. 각 행을 클릭하면 그 조건 그대로 해당 전략 페이지로,
  오른쪽 링크로는 그 히트맵 페이지로 이동합니다. **스윕 상한(%)**은 gap·수량·매수
  트리거처럼 기본 상한이 50%였던 축들에 공통으로 적용됩니다.
- **`/best_heatmap` (전략별 기간 비교 히트맵)**: `/best`의 6개 전략 × **6개 기간
  (180/90/60/30/14/7일)**의 최고 수익률을 한 번에 비교합니다. 종료일은 모든 기간에
  공통이며(비우면 오늘), 기간마다 따로 데이터를 받지 않고 가장 긴 기간(180일)의
  데이터를 한 번만 받아 필요한 만큼씩 잘라 씁니다. 맨 위 기간 열 머리글을 클릭하면
  그 기간의 `/best`로, 각 칸을 클릭하면 그 조합 그대로 해당 전략의 실제 백테스트
  페이지로 이동합니다. 맨 아래 매도/매수 없음(단순 보유) 행과, 각 칸 괄호 안의
  보유 대비(%)로 전략 성과를 기준선과 비교할 수 있습니다.
- **`/best_sweep_heatmap` (전략별 스윕 상한 비교 히트맵)**: 6개 전략이 **스윕 상한(gap·
  수량·매수 트리거 축)**을 넓혀갈 때 최고 수익률이 어떻게 바뀌는지 11개 지점(1, 10,
  20, ..., 100%)으로 한 번에 비교합니다. 스윕 상한 N에서의 최고 수익률은 그 축들을
  1~N까지만 스윕했을 때의 최고값과 같다는 점을 이용해, 전략마다 1~100 전체를 한 번만
  계산한 뒤 그 안에서 표시할 11개 N의 최댓값만 뽑아 씁니다(전략당 다시 계산하지
  않음). 같은 행 안에서는 오른쪽(스윕 상한이 클수록)으로 갈수록 수익률이 같거나
  높아집니다. 각 칸을 클릭하면 그 조합 그대로 해당 전략의 실제 백테스트 페이지로
  이동합니다.

위 페이지들은 기본적으로 로컬 CSV만 읽으므로 매번 네이버에 다시 접속하지 않습니다. 다만
요청한 종목+기간에 맞는 로컬 데이터가 없거나 부족하면 그때(부족한 구간만) 네이버에서 가져와
`data/`에 채웁니다(자세한 동작은 [로컬 데이터 파일명](#로컬-데이터-파일명) 참고).

## 그리드 매매 전략 (`grid_trade_strategy`)

### 기본 설정
- 시작 자산: 주식 `initial_shares`주 보유 (기본 100), 현금 0원
- max, min 기준값은 첫날 종가로 시작
- **매매 수량은 절대 주식수가 아니라 시작 보유 주식수 대비 비율(%)로 입력받는다**
  (`resolve_trade_qty(initial_shares, qty_percent)`, 웹 UI의 "매수/매도 수량 (%)" 필드).
  시작 시점에 **한 번만** 절대 수량으로 변환해 이후 보유 주식수가 바뀌어도 그 값을 그대로
  쓴다 — 보유 주식수가 커져도 매번 절대 수량 범위를 새로 가늠할 필요 없이 항상 같은 %
  범위로 의미 있는 백테스트/히트맵 스윕이 가능하다.

### max/min 갱신 정책 (트레일링 고점/저점)
- **상시 갱신**: 매매 발생 여부와 무관하게, 그날 주가가 현재 max보다 높으면 max를,
  현재 min보다 낮으면 min을 즉시 그 가격으로 갱신한다 (최근 고점/저점을 계속 추적).
- **매매 발생 시 리셋**: 매도가 일어나면 max를 그 매도가로 리셋(그 지점부터 새 고점을
  다시 추적), 매수가 일어나면 min을 그 매수가로 리셋(그 지점부터 새 저점을 다시 추적).

### 매도 조건 (모두 충족해야 함, `no_sell=True`면 매도 자체를 하지 않음)
- 현재가 ≤ max × (1 − 매도gap%)
- 보유 주식수 ≥ 매매 수량
- **전날 종가보다 하락한 날일 것**
- → 매매 수량만큼 정량 매도 (부분매도 없음)

### 매수 조건 (모두 충족해야 함, `no_buy=True`면 매수 자체를 하지 않음)
- 현재가 ≥ min × (1 + 매수gap%) — 매수gap을 따로 지정하지 않으면 매도gap과 동일한 값을 사용
- **전날 종가보다 상승한 날일 것**
- 매수 수량은 `allow_negative_cash` 옵션에 따라 둘 중 하나:
  - **기본값(False)**: `min(매매 수량, 현금 // 현재가)` — **쌓인 현금 한도 내에서만** 매수하며,
    현금이 부족하면 살 수 있는 만큼만 매수한다 (매수 가능 수량이 0이면 거래 자체가 발생하지 않음)
  - **True (초창기 모델)**: 현금 잔고와 무관하게 매매 수량을 그대로 매수한다. 현금이 마이너스가
    될 수 있다.
- **매수 조건이 충족되면, 실제로 살 수 있었는지(현금 충분 여부)와 무관하게 min을 그 가격으로
  갱신한다.** 그렇지 않으면 현금이 부족해 못 산 경우 오래된 저점이 계속 남아, 이후 아주 작은
  반등에도 매수 조건이 계속 참이 되고, 한참 뒤 현금이 생겼을 때 이미 많이 오른 가격을 옛
  저점 기준으로 잘못 판단해 사버리는 문제가 생긴다.

### "전날 대비" 조건을 넣은 이유
매도는 max 기준, 매수는 min 기준으로 서로 다른 기준점을 보기 때문에, 같은 날 가격이
"그날 자체로는 올랐지만 옛 고점보다는 여전히 많이 낮은" 경우 두 조건이 동시에 참이 되어
하루에 매도와 매수가 동시에 발생할 수 있었다. 이는 실제 매매에서는 있을 수 없는 일이라,
"그날 상승이면 매수만, 하락이면 매도만" 가능하도록 막아 동시 발생을 원천 차단했다.

### 매매일지에 기록되는 항목
| 필드 | 설명 |
|---|---|
| 날짜, 구분(매도/매수), 가격, 수량 | 기본 거래 정보 |
| 현금잔고, 보유주식수 | 거래 직후 상태 |
| max, min | 그 거래를 판단할 때 쓰인 고점/저점 스냅샷 |
| 등락률 | 매도는 (가격−max)/max×100, 매수는 (가격−min)/min×100 |
| 주식평가금액 | 가격 × 거래 직후 보유주식수 |

### 최종 반환값
`주가`, `보유주식수`, `주식_평가금액`, `현금`, `적립금`(이익 회수 미사용 시 0),
`total`(=주식평가금액+현금+적립금), `매도횟수`, `매수횟수`, `매매일지`, `자산추이`
(이익 회수 사용 시 `이익회수횟수`, `이익회수일지`도 추가됨)

`자산추이`는 첫날부터 마지막 날까지 **매일** 스냅샷(거래 발생 여부와 무관)을 담은 리스트로,
각 항목은 `날짜`·`주가`·`현금`·`보유주식수`·`주식평가금액`·`적립금`·`total`을 가진다.
매매일지/이익회수일지는 거래·회수가 발생한 날에만 기록되는 것과 달리, 자산추이는 매일의
값을 빠짐없이 담아 그래프로 그릴 수 있게 한다.

`/grid_trade` 페이지는 이 결과로 시작자산 대비 수익/수익률, "매매 안 했을 때(단순 보유)
최종자산"과의 비교, 종가 그래프 위 매도(빨강)/매수(파랑) 마커, 매매일지 테이블까지 보여준다.
같은 그래프에 **오른쪽(y2) 축**으로 총자산·주식평가금액·현금 선을 겹쳐 그릴 수 있으며,
각각 체크박스로 켜고 끌 수 있다(총자산만 기본으로 켜져 있음). `/profit_recovery` 페이지는
그리드 매수/매도 없이 이익 회수 이벤트만 사용하므로, 매도/매수 마커 대신 이익회수(★)
마커와 적립금 y2 토글을 보여준다(자세한 내용은 아래 [이익 회수](#이익-회수) 참고).

## 일별 역추세 매매 전략 (`daily_reversal_strategy`)

`grid_trade_strategy()`와 달리 gap 임계값도, max/min 트레일링 기준도, 이익 회수 기능도 전혀
없는 가장 단순한 전략이다. 매도 수량(`sell_qty`)과 매수 수량(`buy_qty`)을 독립적으로 지정할
수 있다.

- 시작: 주식 `initial_shares`주 보유, 현금 0원
- **전날 종가보다 오른 날**: `sell_qty`만큼 매도한다. 단, 보유 주식수가 `sell_qty`보다
  적으면 매도하지 않는다(공매도 없음). `sell_above_start_asset_only=True`면 추가로 **그
  시점 평가자산(주식평가금액+현금)이 시작 자산(`initial_shares` × 첫날 종가)보다 높을
  때만** 매도한다 (아직 시작 자산을 회복하지 못한 상태의 반등에는 팔지 않고 계속 보유).
- **전날 종가보다 내린 날**: `buy_qty`만큼 매수를 시도한다.
  - `allow_negative_cash=True`면 현금 잔고와 무관하게 항상 `buy_qty`만큼 그대로 매수한다
    (현금이 마이너스가 될 수 있음).
  - `False`(기본)면 "쌓인 현금으로 살 수 있는 만큼"과 `buy_qty` 중 작은 값만큼만 매수한다
    (`grid_trade_strategy()`의 기본 매수 로직과 동일). 그마저도 0이면 매수하지 않는다.
- 전날과 같은 날: 아무 것도 하지 않는다.

반환값은 `grid_trade_strategy()`와 비슷하지만 `max`/`min`/`등락률`이 없고(애초에 기준점이
없으므로) 이익 회수 관련 키도 없다: `주가`, `보유주식수`, `주식_평가금액`, `현금`,
`total`(=주식_평가금액+현금), `매도횟수`, `매수횟수`, `매매일지`, `자산추이`. 매매일지의 각
행에는 `매매안했을때자산`(그 시점까지 매매 없이 시작 주식수만 들고 있었을 때 자산)과
`차이`(실제 자산과의 차이)도 함께 담긴다.

`/daily_reversal` 페이지는 요약 카드·차트(종가 + 매도/매수 마커 + 총자산/주식평가금액/현금/매매
안 했을 때 총자산 y2 토글)·매매일지 테이블을 보여준다. "현금 부족해도 매수"와 "시작
자산보다 높을 때만 팔기"(기본 켜짐) 체크박스로 위 옵션을 켜고 끌 수 있다.

`compute_daily_heatmap()`은 이 전략 전용 히트맵 계산 함수로, `compute_profit_heatmap()`과
동일한 패턴(중복 제거, top10/bottom10, ranked/raw_ranked)을 매도수량% × 매수수량% 축에
적용한다. `/daily_reversal_heatmap` 페이지가 이를 사용한다.

## 고정기준가 역추세 매매 전략 (`daily_reference_strategy`)

`grid_trade_strategy()`/`daily_gap_strategy()`처럼 gap 기준 매매지만, **트레일링이 아니다**
— 매일 새 고점/저점을 따라가며 계속 갱신되는 대신, **매매가 일어날 때만** 그 거래가로
갱신되는 정적인 **기준가** 하나만 쓴다.

- 시작: 주식 `initial_shares`주 보유, 현금 0원, 기준가 = 첫날 종가
- **매도**: 현재가가 기준가 대비 `up_gap_percent`% 이상 오르면 `trade_qty`만큼 매도하고
  기준가를 그 매도가로 리셋한다. 보유 주식수가 `trade_qty`보다 적으면 건너뛴다(공매도
  없음 — 이 경우 기준가도 갱신되지 않는다).
- **매수**: 현재가가 기준가 대비 `down_gap_percent`% 이상 내리면 매수를 시도한다.
  `down_gap_percent`를 지정하지 않으면(`None`) `up_gap_percent`와 동일한 값을 쓴다.
  - `allow_negative_cash=True`면 현금 잔고와 무관하게 `trade_qty`를 그대로 매수한다(현금이
    마이너스가 될 수 있음).
  - `False`(기본)면 "쌓인 현금으로 살 수 있는 만큼"과 `trade_qty` 중 작은 값만큼만
    매수한다. 매수 신호가 뜨면 실제로 살 수 있었는지와 무관하게 기준가를 그 시점 가격으로
    갱신한다(다른 전략들과 동일한 이유 — 현금 부족으로 못 산 경우 옛 기준가가 계속 남아
    이후 작은 반등에도 매수 조건이 계속 참이 되는 문제를 막는다).
- 기준가가 하나뿐이고 상승/하락 조건이 서로 반대 방향이라, 하루에 매도·매수가 동시에
  발생하는 일이 애초에 있을 수 없다(`grid_trade_strategy()`의 "전날 대비" 게이트가
  필요 없는 이유).
- 매도/매수 수량이 `trade_qty` 하나로 공유된다(`daily_reversal_strategy()`처럼 독립
  지정이 아님).

매매일지의 각 행에는 `max`/`min` 대신 `기준가`(그 거래를 판단할 때 쓰인 기준가 스냅샷)
하나만 담기고, `등락률`은 `(가격-기준가)/기준가×100`이다. 나머지 반환값 구조는
`daily_gap_strategy()`와 동일하다.

`/daily_reference` 페이지는 요약 카드·차트(종가 + 매도/매수 마커 + 총자산/주식평가금액/현금/매매
안 했을 때 총자산 y2 토글)·매매일지 테이블을 보여준다. "현금 부족해도 매수"·"매도 안 함"·
"매수 안 함" 체크박스로 위 옵션을 켜고 끌 수 있다.

`DAILY3_HEATMAP_FEATURES`(`up_gap`/`down_gap`/`qty_pct` 3개 피쳐)와
`compute_daily_reference_heatmap_2d()`는 이 전략 전용 통합 히트맵 계산 함수로,
`compute_profit_heatmap_2d()`(`HEATMAP_FEATURES`, 4개 피쳐 중 2개 축 선택)와 동일한 패턴을
3개 피쳐로 적용한다. 축으로 고르지 않은 나머지 한 피쳐는 `fixed` dict의 고정값을 쓰되,
**`down_gap`이 고정값이고 값이 없으면(None)** `daily_reference_strategy()`의 기본 동작과
동일하게 그 셀의 상승gap 값을 그대로 하락gap으로 쓴다(미러링). 상승gap은 스스로가 기준이
되는 값이라 미러링할 대상이 없으므로, 상승gap이 축이 아니면 고정값이 반드시 있어야 한다
(수량%도 마찬가지). `/daily_reference_heatmap` 페이지가 이를 사용한다.

## 이익 회수

`/profit_recovery` 페이지는 `grid_trade_strategy()`를 그리드 매수/매도 없이(`no_sell`·
`no_buy` 항상 켬) `profit_gap_percent`/`profit_recover_percent`만 넘겨서 호출한다 — 아래
규칙이 그 페이지가 계산하는 전부다.

- 매수/매도 로직과 **완전히 독립적으로** 동작한다(원래 grid_trade_strategy()에서는
  max/min, 매도·매수 횟수에 영향을 주지 않는 별도 이벤트로 설계되어 있다).
- **자본금**(`capital`)을 기준으로 삼는다. 지정하지 않으면 **시작 자산**
  (`initial_shares` × 첫날 종가)을 자본금으로 사용한다. 자본금은 고정값이며 백테스트 중
  갱신되지 않는다.
- 매일 확인한다: 평가금액(주식평가금액 + 현금)이 자본금 대비 `profit_gap_percent`% 이상
  벌었으면 이벤트 발동.
- 발동 시 **평가차익 = 평가금액 − 자본금**. 이 중 `profit_recover_percent`%(1~100)에
  해당하는 금액을 **현금에서 먼저 충당**하고, 모자란 만큼 **주식을 추가로 매도**해서(현재가
  기준, 정수 주식수로 내림 처리) 마련한 뒤 "적립금"으로 옮긴다.
- 적립금은 이후 매수 자금으로 쓰이지 않으며(손대지 않음), 최종 `total` 계산에는 그대로
  합산된다 (`total = 주식_평가금액 + 현금 + 적립금`).
- 자본금은 고정값이라 이벤트 발동 후 별도로 갱신하지 않는다. 회수로 평가금액 자체가
  줄어들기 때문에, 다시 자본금 대비 `profit_gap_percent`%만큼 벌어야 재발동한다.
- **시작 자산도 이 자본금을 그대로 사용한다.** `/profit_recovery` 결과 대시보드의 "시작
  자산"(수익/수익률·"매매 안 했을 때 최종자산" 비교 기준)은 `initial_shares × 첫날 종가`가
  아니라, 위에서 정한 자본금(지정 안 했으면 여전히 `initial_shares × 첫날 종가`) 값을
  그대로 사용한다.

`/profit_recovery` 페이지는 **이익회수일지**(날짜·자본금·가격·평가금액·평가차익·현금사용액·
매도주식수·회수액·적립금잔고 등)를 테이블로 보여주고, 주가 차트에도 이익회수 시점을
별표(★) 마커로 표시한다.

## 히트맵 계산 (`compute_profit_heatmap`)

- `_run_grid_fast()`로 매매일지 기록 없이 빠르게 반복 계산한다 (`grid_trade_strategy()`와 완전히
  동일한 매매 로직을 공유하므로 결과가 서로 어긋나지 않는다).
- gap × 수량 조합별 수익률과 최종자산을 모두 계산해 다음을 반환한다: 전체 그리드(`grid`),
  최고/최저 조합(`best`/`worst`), **수익률 상위 10 / 하위 10** 조합 목록(`top10`/`bottom10`),
  시작 자산(`initial_asset`). 각 조합에는 수익률(`profit_pct`)뿐 아니라 최종자산(`total`)도
  함께 담겨 있어 결과 화면(카드·표·히트맵 칸 툴팁)에 원화 금액으로도 표시된다.
- `capital`을 지정하면 수익률/최종자산 계산의 기준이 되는 시작 자산을 그 값으로 쓴다
  (지정하지 않으면 `initial_shares × 첫날 종가`를 그대로 사용). `/grid_trade_heatmap` 폼에도
  "자본금"(비우면 시작 자산) 입력 필드가 있다.
- 성능: 1,000일치 데이터 기준으로 2,500개 조합(50×50) 계산에 약 0.5초.
- gap이 커질수록(예: 40~50%) 가격이 그만큼 크게 움직여야 거래가 트리거되므로, 사실상 거래가
  거의 발생하지 않게 된다. gap이 "보유 자산의 몇 %를 판다"는 뜻이 아니라 **"가격이 몇 % 움직이면
  거래를 시작한다"는 임계값**이기 때문에, gap을 아무리 키워도 자산이 사라지는 일은 없다.

## 가격 통계 (`compute_price_stats`)

`/` 페이지(가격 통계 절)가 사용하는 함수로, 매매 전략과 무관하게 종가만으로 다음을 계산한다.

- 각 날짜를 전날 종가와 비교해 **상승**(`종가 > 전날 종가`)/**하락**(`종가 < 전날 종가`)/
  **보합**(같음)으로 분류하고, 상승/하락 일수·비율을 집계한다.
- **연속 상승·연속 하락(streak)**: 방향이 이어지는 구간의 길이를 각각 모아 분포로 만든다
  (보합은 연속을 끊는다). 예: `up,up,down,up,up,up` → 연속 상승 길이 `[2, 3]`, 연속 하락
  길이 `[1]`.
- **등락률(%) 분포**: 상승일·하락일 각각의 `(종가−전날종가)/전날종가×100`을 모아 평균·
  최댓값(하락은 최솟값, 즉 가장 큰 낙폭)을 계산하고, 히스토그램용으로 **정수(1%p)
  단위로 반올림**해 값별 개수를 센다(`compute_price_stats(df, pct_round_ndigits=0)`,
  필요하면 인자로 다른 자리수를 넘길 수 있다). 연속 일수(streak) 히스토그램은 애초에
  정수(일수)라 반올림 없이 그대로 집계한다.
- 최솟값~최댓값 구간을 빈틈없이 채워서 반환하므로(값이 없는 칸은 개수 0), 히스토그램
  막대 사이에 빈 구간이 있어도 그대로 드러난다.
- **연속 일수별 평균/합계 등락률** (`_streak_length_agg`): 연속 상승·하락 구간마다 두
  가지 값을 함께 기록한다 — `평균등락률`(그 구간에 속한 날들의 일별 등락률 평균, "하루
  평균 기세")과 `총등락률`(**구간 하나 안에서** 그 며칠간의 등락률을 합친 값 — 예: 2일
  연속 상승이면 그 2일의 등락률 합. 일별 등락률을 단순 합산한 근사치가 아니라, 구간
  시작 전날 종가 대비 마지막 날 종가의 실제 등락률로 계산해 복리까지 정확히 반영한다).
  같은 길이의 구간이 여러 개 있으면 세 값을 길이별로 계산한다:
  - `1일평균`: 그 구간들의 `평균등락률`을 평균 낸 값 — "그 길이 구간 하루 동안 보통
    얼마나 움직이는지".
  - `합계평균`: 서로 다른 구간끼리 더하는 게 아니라, `1일평균`과 완전히 동일한 방식으로
    그 구간들의 `총등락률`끼리 평균 낸 값.
  - `합계최대`: 그 구간들의 `총등락률` 중 절댓값이 가장 큰 값(상승은 곧 최댓값, 하락은
    곧 최솟값 = 가장 큰 낙폭).

  이 세 값이 `/`의 "연속 일수별 1일 평균/합계 등락률" 그래프다: x축=연속 일수,
  왼쪽 y축=`1일평균`(항상 표시), 오른쪽 y2축=`합계평균`(기본 켜짐)·`합계최대`(기본
  꺼짐) — 두 y2 계열은 그래프 위 체크박스로 각각 켜고 끌 수 있다. 구간이 하나도 없는
  길이는 결과에서 아예 빼버린다(0으로 채우면 관측된 적 없는 길이가 관측된 것처럼
  보이기 때문).

## 로컬 데이터 파일명

조회한 데이터는 종목당 파일 하나, `data/{종목코드}.csv`로 저장됩니다(예: `102110.csv`).
네이버 시세는 조회 시점과 무관하게 같은 과거 날짜는 항상 같은 값이라, 이 파일 하나가 그
종목의 실제 날짜로 색인된 **롤링 캐시** 역할을 합니다 — 최대 보관 기간은 **2년**이며, 그보다
오래된 데이터는 저장할 때마다 잘라냅니다.

모든 페이지(`/grid_trade`·`/profit_recovery`·`/daily_reversal`·`/daily_gap`·`/daily_reference`·`/capital_recovery`·
`/daily_reversal_heatmap`~`/profit_recovery_heatmap`·`/best`, 메인 페이지 `/` 포함)는 **종목 코드**와
**종료일**(`end_date`, 비우면
오늘) + **시작일**(`start_date`) **또는 기간**(`period`) 중 하나를 입력받습니다. 시작일을
입력하면 기간은 거기서 자동으로 역산되고, 시작일 없이 기간만 입력하면 시작일이 종료일에서
그만큼 뺀 날짜로 자동 계산됩니다(둘 다 비우면 기본 30일).

요청한 범위가 로컬 캐시에 이미 있으면 네이버를 다시 부르지 않고 그 파일에서 바로 잘라
보여줍니다. 캐시보다 최신 데이터가 필요하면(예: 어제 이후 데이터가 없음) 그 차이만큼만,
캐시보다 더 오래된 과거가 필요하면 그만큼만 추가로 받아 기존 파일에 합칩니다 — 항상 전체를
다시 받지 않습니다. 시작일이 보관 기간(2년)보다 과거면 그만큼만 받고 화면에 안내 문구가
표시됩니다.

## 참고

- 네이버 금융은 별도 API 키가 필요 없는 대신, 페이지를 스크래핑하는 방식이라
  네이버 쪽 페이지 구조가 바뀌면 코드 수정이 필요할 수 있습니다.
- 과도하게 빠른 요청을 막기 위해 `core.py`의 `sleep` 파라미터로 페이지 요청 간
  약간의 대기시간을 두고 있습니다.
- 이 앱을 실행하려는 환경에서 `finance.naver.com`으로의 아웃바운드 네트워크 접속이
  허용되어 있어야 합니다.
- 백테스트/히트맵 페이지는 네이버에 부하를 주지 않도록 로컬 CSV만 사용합니다. 새 종목/기간을
  다루려면 먼저 메인 페이지에서 한 번 조회해주세요.
