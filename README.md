# 네이버 주식 시세 조회 앱

종목 코드와 기간(오늘부터 n일 전)을 입력하면 네이버 금융에서 일별 시세를 가져오는 웹 앱입니다.
그리드(등락폭) 매매 전략 백테스트 및 매매일지 확인 기능도 포함되어 있습니다.

## 구성

- `core.py` — 네이버 금융 스크래핑 + 그리드 매매 전략 계산 로직. **쉘에서 단독 실행/테스트 가능**
- `app.py` — Flask 웹 서버 (시세 조회 `/`, 백테스트 `/backtest`, 일별 방향 매매 `/daily`,
  히트맵 `/heatmap`·`/heatmap2`·`/heatmap3`·`/heatmap4`)
- `templates/index.html` — 시세 조회 페이지 (입력 폼 + 결과 테이블 + 차트, Chart.js)
- `templates/backtest.html` — 백테스트 페이지 (그리드 매매 + 선택적 이익 회수)
- `templates/daily.html` — 일별 방향 매매 백테스트 페이지 (gap 없이 전날 대비 상승/하락만 봄)
- `templates/heatmap.html` — gap × 매매수량 수익률 히트맵 페이지
- `templates/heatmap2.html` — gap × 이익회수gap 수익률 히트맵 페이지
- `templates/heatmap3.html` — **(실험적)** 4개 피쳐 중 2개를 축으로 골라 쓰는 통합 히트맵.
  `/heatmap`·`/heatmap2`를 일반화한 것으로, 검증되면 그 둘을 대체할 예정.
- `templates/heatmap4.html` — 일별 방향 매매 전용 히트맵 (매도수량% × 매수수량%)
- `templates/daily3.html` — 일별 방향3 백테스트 페이지 (정적 기준가, 트레일링 아님)
- `templates/heatmap6.html` — 일별 방향3 통합 히트맵 (상승gap·하락gap·수량% 중 2개 축 선택)
- `templates/stats.html` — 가격 통계 페이지 (`/stats`, 상승/하락 일수·연속 일수 분포·등락률 분포)
- `templates/_nav.html` — 모든 페이지가 공유하는 상단 네비게이션 partial
- `templates/_csv_file_selector.html` — 종목/생성일자/기간 선택 UI를 모든 페이지가 공유하는 partial
- `static/js/csv_selector.js` — 위 partial이 사용하는 공용 JS(종목→생성일자→기간 연동)
- `data/` — 조회한 시세가 자동 저장되는 로컬 CSV 폴더 (기본적으로 여기서 읽고, 없거나 부족할 때만 네이버에서 채움)
- `requirements.txt` — 의존 패키지

## 설치 및 실행

```bash
pip install -r requirements.txt

# 1) 쉘에서 핵심 라이브러리 단독 테스트
python core.py 005930 --days 30
python core.py 005930 -d 90 --csv samsung.csv

# 2) 쉘에서 그리드 매매 백테스트까지 함께 실행
python core.py 102110 -d 180 --gap 5 --qty 10

# 3) 웹 서버 실행
python app.py
# -> 브라우저에서 http://localhost:8000 접속
```

## 웹 페이지 안내

- **`/` (메인)**: 종목 코드 + 기간을 입력해 네이버에서 시세를 조회합니다. 조회 결과는 자동으로
  `data/{code}_{days}days_{조회일자}.csv`에 저장되어, 이후 백테스트/히트맵 페이지에서 재사용됩니다.
- **`/backtest` (백테스트)**: 저장된 CSV로 특정 gap/수량 조합 하나를 백테스트해 매매일지와
  수익을 보여줍니다. **"🏦 이익 회수 사용"** 체크박스로 이익 회수 기능을 켜고 끌 수 있습니다.
  자세한 규칙은 아래 [이익 회수](#이익-회수) 참고.
- **`/daily` (일별 방향 매매)**: gap이나 고점/저점 추적 없는 가장 단순한 전략. 전날 종가보다
  오른 날은 매도, 내린 날은 매수를 시도합니다 (같으면 매매 없음). **매도 수량(%)과 매수
  수량(%)을 독립적으로 지정**하며, 둘 다 시작 보유 주식수 대비 %로 정합니다. "현금 부족해도
  매수"를 체크하면 현금 잔고와 무관하게 항상 그대로 매수하고(현금이 마이너스가 될 수 있음),
  체크하지 않으면 쌓인 현금 범위 내에서만 매수합니다. "시작 자산보다 높을 때만 팔기"(기본
  켜짐)를 체크하면 그 시점 평가자산이 시작 자산을 회복하지 못한 상태에서는 매도하지 않습니다.
  매도는 보유 주식수가 모자라면 건너뜁니다(공매도 없음).
  자세한 규칙은 아래 [일별 방향 매매 전략](#일별-방향-매매-전략-daily_reversal_strategy) 참고.
- **`/heatmap` (히트맵)**: gap 1~50%(1% 단위) × 매매수량 1~50%(1% 단위, 시작 보유 주식수
  대비) = 2,500개 조합의 수익률과 최종자산을 한 번에 계산해 색상 히트맵으로 보여줍니다.
  자본금(비우면 시작 자산) 필드로 수익률 계산 기준을 바꿀 수 있습니다. 최대/최소 수익률
  조합을 큼직한 카드로 보여주고, **수익률 상위 10 / 하위 10** 조합을 각각 표
  (순위·gap·수량·수익률·최종자산)로 정리해서 보여줍니다. 히트맵의 각 칸, 상위·하위 10 표의
  각 행, 최대/최소 수익률 카드 — 모두 클릭하면 그 조건 그대로(이익 회수 사용 끈 상태로)
  `/backtest` 페이지로 이동합니다. **대표 수량 분석** 카드는 수량%별로 매매가 실제 발생한
  gap들만 모아 수익률의 중앙값을 계산해 "gap을 모르는 상태에서 가장 무난한 수량"을 추천하고,
  클릭하면 그 수량이 채워진 채로 `/heatmap2`로 이동합니다 (자세한 계산은 아래
  [대표 수량 분석](#대표-수량-분석) 참고).
- **`/heatmap2` (이익회수 히트맵)**: 매매 gap 1~50% × 이익회수 gap 1~100%(둘 다 1% 단위)
  조합의 수익률을 계산합니다. 거래 수량(%)·회수율·자본금은 폼에서 고정값으로 입력합니다.
  마찬가지로 각 칸/카드를 클릭하면 그 조건 그대로(이익 회수 사용 켠 상태로) `/backtest`
  페이지로 이동합니다.
- **`/heatmap3` (통합 히트맵, 실험적)**: 주가gap·매매수량·이익gap·이익회수율 4개 중 2개를
  X축/Y축으로 직접 골라 스윕하는 `/heatmap`·`/heatmap2`의 일반화 버전입니다. 주가gap+매매수량,
  이익gap+이익회수율이 각각 한 줄에 묶여 있고, 축으로 고르지 않은 나머지 두 피쳐는 그 줄에서
  고정값으로 입력합니다. 이익 회수 로직은 축 선택과 무관하게 **항상 켜진 채로** 계산됩니다
  (자세한 계산은 아래 [히트맵 계산](#히트맵-계산-compute_profit_heatmap) 참고). 같은 피쳐를
  X/Y 양쪽에 고르면 자동으로 서로 바꿔치기됩니다. `/heatmap`·`/heatmap2`와 동일하게
  카드/표/칸을 클릭하면 그 조건 그대로 `/backtest` 페이지로 이동합니다. 검증되면 이 페이지가
  `/heatmap`·`/heatmap2`를 대체할 예정입니다.
- **`/heatmap4` (일별 매매 히트맵)**: `/daily`(일별 방향 매매) 전용 히트맵으로, 매도수량%
  1~50% × 매수수량% 1~50%(둘 다 1% 단위, 시작 보유 주식수 대비) 조합의 수익률을 계산합니다.
  gap 개념이 없는 전략이라 두 축 모두 수량 비율입니다. 나머지 UI(최대/최소 카드, 상위/하위
  10, 순위별 수익률 그래프, 전체 순위 목록, 클릭 시 `/daily`로 이동)는 `/heatmap`과 동일한
  패턴입니다.
- **`/daily3` (일별 방향3)**: 정적인 **기준가** 기준 전략. 기준가는 첫날 종가로 시작해서
  **매매가 일어날 때만** 그 거래가로 갱신되고, 그리드 매매·`/daily2`처럼 매일 새 고점/저점을
  따라가며 갱신되는 트레일링 방식이 아닙니다. 현재가가 기준가 대비 **상승gap% 이상 오르면
  매도**, **하락gap% 이상 내리면 매수**합니다(하락gap을 비워두면 상승gap과 동일하게 취급).
  매도/매수 수량은 하나의 값(시작 보유 주식수 대비 %)을 공유합니다. **"현금 부족해도
  매수"** 체크박스로 현금 잔고와 무관하게 매수할지(마이너스 현금 허용) 정할 수 있습니다.
  자세한 규칙은 아래 [일별 방향3 전략](#일별-방향3-전략-daily_reference_strategy) 참고.
- **`/heatmap6` (일별 방향3 통합 히트맵, 축 선택형)**: `/daily3`(일별 방향3) 전용 히트맵으로,
  **상승gap · 하락gap · 매도/매수 수량** 3개 중 2개를 X축/Y축으로 직접 골라 스윕합니다
  (`/heatmap3`과 같은 방식). 축으로 고르지 않은 나머지 하나는 고정값으로 입력합니다. 기본
  설정은 X축=상승gap, Y축=수량%이고, 이때 고정값인 하락gap을 비워두면
  `daily_reference_strategy()`의 기본 동작과 동일하게 그때그때의 상승gap 값을 그대로
  하락gap으로 씁니다("하락gap = 상승gap"). 나머지 UI(최대/최소 카드, 상위/하위 10, 순위별
  수익률 그래프, 전체 순위 목록, 클릭 시 `/daily3`로 이동)는 `/heatmap3`과 동일한 패턴입니다.
- **`/stats` (가격 통계)**: 매매 전략과 무관하게, 전날 종가 대비 **상승/하락/보합 일수**와
  비율, **연속 상승·연속 하락(streak) 일수 분포**, 상승일·하락일 각각의 **등락률(%) 분포**
  (평균·최댓값 포함)를 보여줍니다. 등락률 히스토그램은 정수(1%p) 단위로 반올림해
  집계합니다. 추가로 **연속 일수별 1일 평균/합계 등락률** 그래프(x축=연속 일수)를
  상승/하락 각각 보여줍니다: 왼쪽 y축의 **1일 평균**(항상 표시)은 하루 평균 기세, 오른쪽 y2축의
  **합계평균**(기본 켜짐)·**합계최대**(기본 꺼짐, 체크박스로 켤 수 있음)는 구간 하나
  안에서의 등락률 합을 각각 평균·절댓값 최대로 집계한 값입니다(자세한 계산은
  [`compute_price_stats`](#가격-통계-compute_price_stats) 참고).

위 페이지들은 기본적으로 로컬 CSV만 읽으므로 매번 네이버에 다시 접속하지 않습니다. 다만
요청한 종목+생성일자+기간에 맞는 로컬 데이터가 없거나 부족하면 그때만 네이버에서 가져와
`data/`에 채웁니다(자세한 동작은 [로컬 데이터 파일명](#로컬-데이터-파일명) 참고).

## 그리드 매매 전략 (`grid_trade_strategy`)

### 기본 설정
- 시작 자산: 주식 `initial_shares`주 보유 (기본 100), 현금 0원
- max, min 기준값은 첫날 종가로 시작
- **매매 수량은 절대 주식수가 아니라 시작 보유 주식수 대비 비율(%)로 입력받는다**
  (`resolve_trade_qty(initial_shares, qty_percent)`, 웹 UI의 "매수/매도 수량 (%)" 필드).
  시작 시점에 **한 번만** 절대 수량으로 변환해 이후 보유 주식수가 바뀌어도 그 값을 그대로
  쓴다 — 보유 주식수가 커져도 매번 절대 수량 범위를 새로 가늠할 필요 없이 항상 같은 %
  범위로 의미 있는 백테스트/히트맵 스윕이 가능하다.

### max/min 갱신 정책 (트레일링 고점/저점)
- **상시 갱신**: 매매 발생 여부와 무관하게, 그날 주가가 현재 max보다 높으면 max를,
  현재 min보다 낮으면 min을 즉시 그 가격으로 갱신한다 (최근 고점/저점을 계속 추적).
- **매매 발생 시 리셋**: 매도가 일어나면 max를 그 매도가로 리셋(그 지점부터 새 고점을
  다시 추적), 매수가 일어나면 min을 그 매수가로 리셋(그 지점부터 새 저점을 다시 추적).

### 매도 조건 (모두 충족해야 함, `no_sell=True`면 매도 자체를 하지 않음)
- 현재가 ≤ max × (1 − 매도gap%)
- 보유 주식수 ≥ 매매 수량
- **전날 종가보다 하락한 날일 것**
- → 매매 수량만큼 정량 매도 (부분매도 없음)

### 매수 조건 (모두 충족해야 함, `no_buy=True`면 매수 자체를 하지 않음)
- 현재가 ≥ min × (1 + 매수gap%) — 매수gap을 따로 지정하지 않으면 매도gap과 동일한 값을 사용
- **전날 종가보다 상승한 날일 것**
- 매수 수량은 `allow_negative_cash` 옵션에 따라 둘 중 하나:
  - **기본값(False)**: `min(매매 수량, 현금 // 현재가)` — **쌓인 현금 한도 내에서만** 매수하며,
    현금이 부족하면 살 수 있는 만큼만 매수한다 (매수 가능 수량이 0이면 거래 자체가 발생하지 않음)
  - **True (초창기 모델)**: 현금 잔고와 무관하게 매매 수량을 그대로 매수한다. 현금이 마이너스가
    될 수 있다.
- **매수 조건이 충족되면, 실제로 살 수 있었는지(현금 충분 여부)와 무관하게 min을 그 가격으로
  갱신한다.** 그렇지 않으면 현금이 부족해 못 산 경우 오래된 저점이 계속 남아, 이후 아주 작은
  반등에도 매수 조건이 계속 참이 되고, 한참 뒤 현금이 생겼을 때 이미 많이 오른 가격을 옛
  저점 기준으로 잘못 판단해 사버리는 문제가 생긴다.

### "전날 대비" 조건을 넣은 이유
매도는 max 기준, 매수는 min 기준으로 서로 다른 기준점을 보기 때문에, 같은 날 가격이
"그날 자체로는 올랐지만 옛 고점보다는 여전히 많이 낮은" 경우 두 조건이 동시에 참이 되어
하루에 매도와 매수가 동시에 발생할 수 있었다. 이는 실제 매매에서는 있을 수 없는 일이라,
"그날 상승이면 매수만, 하락이면 매도만" 가능하도록 막아 동시 발생을 원천 차단했다.

### 매매일지에 기록되는 항목
| 필드 | 설명 |
|---|---|
| 날짜, 구분(매도/매수), 가격, 수량 | 기본 거래 정보 |
| 현금잔고, 보유주식수 | 거래 직후 상태 |
| max, min | 그 거래를 판단할 때 쓰인 고점/저점 스냅샷 |
| 등락률 | 매도는 (가격−max)/max×100, 매수는 (가격−min)/min×100 |
| 주식평가금액 | 가격 × 거래 직후 보유주식수 |

### 최종 반환값
`주가`, `보유주식수`, `주식_평가금액`, `현금`, `적립금`(이익 회수 미사용 시 0),
`total`(=주식평가금액+현금+적립금), `매도횟수`, `매수횟수`, `매매일지`, `자산추이`
(이익 회수 사용 시 `이익회수횟수`, `이익회수일지`도 추가됨)

`자산추이`는 첫날부터 마지막 날까지 **매일** 스냅샷(거래 발생 여부와 무관)을 담은 리스트로,
각 항목은 `날짜`·`주가`·`현금`·`보유주식수`·`주식평가금액`·`적립금`·`total`을 가진다.
매매일지/이익회수일지는 거래·회수가 발생한 날에만 기록되는 것과 달리, 자산추이는 매일의
값을 빠짐없이 담아 그래프로 그릴 수 있게 한다.

`/backtest` 페이지는 이 결과로 시작자산 대비 수익/수익률, "매매 안 했을 때(단순 보유)
최종자산"과의 비교, 종가 그래프 위 매도(빨강)/매수(파랑) 마커, 매매일지 테이블까지 보여준다.
같은 그래프에 **오른쪽(y2) 축**으로 총자산·주식평가금액·현금·적립금(`자산추이` 기반) 선을
겹쳐 그릴 수 있으며, 각각 체크박스로 켜고 끌 수 있다(총자산만 기본으로 켜져 있음; 적립금은
이익 회수를 켰을 때만 토글이 보인다).

## 일별 방향 매매 전략 (`daily_reversal_strategy`)

`grid_trade_strategy()`와 달리 gap 임계값도, max/min 트레일링 기준도, 이익 회수 기능도 전혀
없는 가장 단순한 전략이다. 매도 수량(`sell_qty`)과 매수 수량(`buy_qty`)을 독립적으로 지정할
수 있다.

- 시작: 주식 `initial_shares`주 보유, 현금 0원
- **전날 종가보다 오른 날**: `sell_qty`만큼 매도한다. 단, 보유 주식수가 `sell_qty`보다
  적으면 매도하지 않는다(공매도 없음). `sell_above_start_asset_only=True`면 추가로 **그
  시점 평가자산(주식평가금액+현금)이 시작 자산(`initial_shares` × 첫날 종가)보다 높을
  때만** 매도한다 (아직 시작 자산을 회복하지 못한 상태의 반등에는 팔지 않고 계속 보유).
- **전날 종가보다 내린 날**: `buy_qty`만큼 매수를 시도한다.
  - `allow_negative_cash=True`면 현금 잔고와 무관하게 항상 `buy_qty`만큼 그대로 매수한다
    (현금이 마이너스가 될 수 있음).
  - `False`(기본)면 "쌓인 현금으로 살 수 있는 만큼"과 `buy_qty` 중 작은 값만큼만 매수한다
    (`grid_trade_strategy()`의 기본 매수 로직과 동일). 그마저도 0이면 매수하지 않는다.
- 전날과 같은 날: 아무 것도 하지 않는다.

반환값은 `grid_trade_strategy()`와 비슷하지만 `max`/`min`/`등락률`이 없고(애초에 기준점이
없으므로) 이익 회수 관련 키도 없다: `주가`, `보유주식수`, `주식_평가금액`, `현금`,
`total`(=주식_평가금액+현금), `매도횟수`, `매수횟수`, `매매일지`, `자산추이`. 매매일지의 각
행에는 `매매안했을때자산`(그 시점까지 매매 없이 시작 주식수만 들고 있었을 때 자산)과
`차이`(실제 자산과의 차이)도 함께 담긴다.

`/daily` 페이지는 `/backtest`와 같은 형태로 요약 카드·차트(종가 + 매도/매수 마커 +
총자산/주식평가금액/현금/매매 안 했을 때 총자산 y2 토글)·매매일지 테이블을 보여준다.
"현금 부족해도 매수"와 "시작 자산보다 높을 때만 팔기"(기본 켜짐) 체크박스로 위 옵션을
켜고 끌 수 있다.

`compute_daily_heatmap()`은 이 전략 전용 히트맵 계산 함수로, `compute_profit_heatmap()`과
동일한 패턴(중복 제거, top10/bottom10, ranked/raw_ranked)을 매도수량% × 매수수량% 축에
적용한다. `/heatmap4` 페이지가 이를 사용한다.

## 일별 방향3 전략 (`daily_reference_strategy`)

`grid_trade_strategy()`/`daily_gap_strategy()`처럼 gap 기준 매매지만, **트레일링이 아니다**
— 매일 새 고점/저점을 따라가며 계속 갱신되는 대신, **매매가 일어날 때만** 그 거래가로
갱신되는 정적인 **기준가** 하나만 쓴다.

- 시작: 주식 `initial_shares`주 보유, 현금 0원, 기준가 = 첫날 종가
- **매도**: 현재가가 기준가 대비 `up_gap_percent`% 이상 오르면 `trade_qty`만큼 매도하고
  기준가를 그 매도가로 리셋한다. 보유 주식수가 `trade_qty`보다 적으면 건너뛴다(공매도
  없음 — 이 경우 기준가도 갱신되지 않는다).
- **매수**: 현재가가 기준가 대비 `down_gap_percent`% 이상 내리면 매수를 시도한다.
  `down_gap_percent`를 지정하지 않으면(`None`) `up_gap_percent`와 동일한 값을 쓴다.
  - `allow_negative_cash=True`면 현금 잔고와 무관하게 `trade_qty`를 그대로 매수한다(현금이
    마이너스가 될 수 있음).
  - `False`(기본)면 "쌓인 현금으로 살 수 있는 만큼"과 `trade_qty` 중 작은 값만큼만
    매수한다. 매수 신호가 뜨면 실제로 살 수 있었는지와 무관하게 기준가를 그 시점 가격으로
    갱신한다(다른 전략들과 동일한 이유 — 현금 부족으로 못 산 경우 옛 기준가가 계속 남아
    이후 작은 반등에도 매수 조건이 계속 참이 되는 문제를 막는다).
- 기준가가 하나뿐이고 상승/하락 조건이 서로 반대 방향이라, 하루에 매도·매수가 동시에
  발생하는 일이 애초에 있을 수 없다(`grid_trade_strategy()`의 "전날 대비" 게이트가
  필요 없는 이유).
- 매도/매수 수량이 `trade_qty` 하나로 공유된다(`daily_reversal_strategy()`처럼 독립
  지정이 아님).

매매일지의 각 행에는 `max`/`min` 대신 `기준가`(그 거래를 판단할 때 쓰인 기준가 스냅샷)
하나만 담기고, `등락률`은 `(가격-기준가)/기준가×100`이다. 나머지 반환값 구조는
`daily_gap_strategy()`와 동일하다.

`/daily3` 페이지는 `/daily2`와 같은 형태로 요약 카드·차트(종가 + 매도/매수 마커 +
총자산/주식평가금액/현금/매매 안 했을 때 총자산 y2 토글)·매매일지 테이블을 보여준다.
"현금 부족해도 매수"·"매도 안 함"·"매수 안 함" 체크박스로 위 옵션을 켜고 끌 수 있다.

`DAILY3_HEATMAP_FEATURES`(`up_gap`/`down_gap`/`qty_pct` 3개 피쳐)와
`compute_daily_reference_heatmap_2d()`는 이 전략 전용 통합 히트맵 계산 함수로,
`compute_profit_heatmap_2d()`(`HEATMAP_FEATURES`, 4개 피쳐 중 2개 축 선택)와 동일한 패턴을
3개 피쳐로 적용한다. 축으로 고르지 않은 나머지 한 피쳐는 `fixed` dict의 고정값을 쓰되,
**`down_gap`이 고정값이고 값이 없으면(None)** `daily_reference_strategy()`의 기본 동작과
동일하게 그 셀의 상승gap 값을 그대로 하락gap으로 쓴다(미러링). 상승gap은 스스로가 기준이
되는 값이라 미러링할 대상이 없으므로, 상승gap이 축이 아니면 고정값이 반드시 있어야 한다
(수량%도 마찬가지). `/heatmap6` 페이지가 이를 사용한다.

## 이익 회수

`/backtest` 페이지의 **"🏦 이익 회수 사용"** 체크박스를 켜면(내부적으로
`grid_trade_strategy()`에 `profit_gap_percent`와 `profit_recover_percent`를 **둘 다**
넘기면) 동작한다 (하나만 넘기면 오류). 기본 매수/매도 규칙 위에 다음 규칙이 추가된다
(체크박스를 끄면 이 절은 전혀 적용되지 않고 순수 그리드 매매 결과만 나온다).

- 매수/매도 로직과 **완전히 독립적으로** 동작한다 (max/min, 매도·매수 횟수에 영향을 주지 않음).
- **자본금**(`capital`)을 기준으로 삼는다. 지정하지 않으면 **시작 자산**
  (`initial_shares` × 첫날 종가)을 자본금으로 사용한다. 자본금은 고정값이며 백테스트 중
  갱신되지 않는다.
- 매일, **매수/매도 판단보다 먼저** 확인한다: 평가금액(주식평가금액 + 현금)이 자본금 대비
  `profit_gap_percent`% 이상 벌었으면 이벤트 발동.
- 발동 시 **평가차익 = 평가금액 − 자본금**. 이 중 `profit_recover_percent`%(1~100)에
  해당하는 금액을 **현금에서 먼저 충당**하고, 모자란 만큼 **주식을 추가로 매도**해서(현재가
  기준, 정수 주식수로 내림 처리) 마련한 뒤 "적립금"으로 옮긴다.
- 적립금은 이후 매수 자금으로 쓰이지 않으며(손대지 않음), 최종 `total` 계산에는 그대로
  합산된다 (`total = 주식_평가금액 + 현금 + 적립금`).
- 자본금은 고정값이라 이벤트 발동 후 별도로 갱신하지 않는다. 회수로 평가금액 자체가
  줄어들기 때문에, 다시 자본금 대비 `profit_gap_percent`%만큼 벌어야 재발동한다.
- **시작 자산도 이 자본금을 그대로 사용한다.** 이익 회수를 켰을 때 `/backtest`·`/heatmap2`
  결과 대시보드의 "시작 자산"(수익/수익률·"매매 안 했을 때 최종자산" 비교 기준)은 더 이상
  `initial_shares × 첫날 종가`가 아니라, 위에서 정한 자본금(지정 안 했으면 여전히
  `initial_shares × 첫날 종가`) 값을 그대로 사용한다. (꺼져 있으면 기존과 동일하게
  `initial_shares × 첫날 종가`를 시작 자산으로 쓴다.)

이익 회수를 켠 채로 계산하면 `/backtest` 페이지는 매매일지 외에 **이익회수일지**
(날짜·자본금·가격·평가금액·평가차익·현금사용액·매도주식수·회수액·적립금잔고 등)를 별도
테이블로 보여주고, 주가 차트에도 이익회수 시점을 별표(★) 마커로 표시한다.

## 히트맵 계산 (`compute_profit_heatmap`)

- `_run_grid_fast()`로 매매일지 기록 없이 빠르게 반복 계산한다 (`grid_trade_strategy()`와 완전히
  동일한 매매 로직을 공유하므로 결과가 서로 어긋나지 않는다).
- gap × 수량 조합별 수익률과 최종자산을 모두 계산해 다음을 반환한다: 전체 그리드(`grid`),
  최고/최저 조합(`best`/`worst`), **수익률 상위 10 / 하위 10** 조합 목록(`top10`/`bottom10`),
  시작 자산(`initial_asset`). 각 조합에는 수익률(`profit_pct`)뿐 아니라 최종자산(`total`)도
  함께 담겨 있어 결과 화면(카드·표·히트맵 칸 툴팁)에 원화 금액으로도 표시된다.
- `capital`을 지정하면 수익률/최종자산 계산의 기준이 되는 시작 자산을 그 값으로 쓴다
  (지정하지 않으면 `initial_shares × 첫날 종가`를 그대로 사용). `/heatmap` 폼에도
  "자본금"(비우면 시작 자산) 입력 필드가 있다.
- 성능: 1,000일치 데이터 기준으로 2,500개 조합(50×50) 계산에 약 0.5초.
- gap이 커질수록(예: 40~50%) 가격이 그만큼 크게 움직여야 거래가 트리거되므로, 사실상 거래가
  거의 발생하지 않게 된다. gap이 "보유 자산의 몇 %를 판다"는 뜻이 아니라 **"가격이 몇 % 움직이면
  거래를 시작한다"는 임계값**이기 때문에, gap을 아무리 키워도 자산이 사라지는 일은 없다.

### 통합 히트맵 (`compute_profit_heatmap_2d`, `/heatmap3`)

`HEATMAP_FEATURES` 딕셔너리에 4개 피쳐(`gap`/`qty_pct`/`profit_gap`/`profit_recover`)의
레이블·스윕 기본범위·고정값 기본값이 정의돼 있다. `compute_profit_heatmap_2d(df, x_feature,
x_values, y_feature, y_values, fixed, ...)`는 `x_feature`/`y_feature`(서로 달라야 함)를
축으로 스윕하고, `fixed` 딕셔너리에 담긴 나머지 두 피쳐 값은 고정한 채 계산한다 —
`profit_gap_percent`/`profit_recover_percent`는 축이든 고정값이든 **항상** `_run_grid_fast()`에
전달되므로, 이익 회수 로직은 두 피쳐가 축으로 선택되지 않았어도 항상 켜진 채로 동작한다.
`compute_profit_heatmap`(gap x qty_pct 고정 조합)과 `compute_profit_heatmap2`(gap x
profit_gap 고정 조합)는 이 함수가 등장하는 특수 케이스와 동일한 결과를 낸다.

## 대표 수량 분석

`/heatmap` 결과에 포함되는 `qty_stats`/`recommended_qty`는, "gap 값을 미리 알 수 없는
상태에서 어떤 매매 수량(%)이 대체로 무난한 성과를 내는지"를 찾기 위한 것이다.

- 수량%(열)마다, 스윕한 gap(행) 전체가 아니라 **실제로 매매(매수 또는 매도)가 1회 이상
  발생한 gap들만** 모아서 수익률의 **중앙값**을 계산한다(`qty_stats[i].median_profit_pct`).
  - 평균이 아니라 중앙값을 쓰는 이유: 극단적인 gap 하나의 수익률에 덜 흔들리기 때문이다.
  - 매매가 아예 없는 gap을 제외하는 이유: gap이 크면(예: 40~50%) 거래가 거의 트리거되지
    않아 어떤 수량을 넣든 결과가 전부 "단순 보유" 수익률로 수렴해버린다. 이런 gap을
    포함해서 집계하면 수량별 차이가 흐려져 대표값의 의미가 없어진다.
- `recommended_qty`는 `qty_stats` 중 중앙값 수익률이 가장 높은 항목이다(스윕한 gap 범위
  안에서 매매가 한 번도 발생하지 않은 수량은 후보에서 제외되며, 전부 그런 경우 `None`).
- `/heatmap` 페이지의 **"대표 수량 분석"** 카드에 수량%별 중앙값 표와 추천 수량이
  표시되고, 추천 수량 카드를 클릭하면 그 값이 채워진 채로 `/heatmap2`(이익회수 히트맵)로
  이동한다 — 거래 수량을 임의로 정한 10%가 아니라, 이 분석으로 뽑은 값을 넣어볼 수 있다.

## 가격 통계 (`compute_price_stats`)

`/stats` 페이지가 사용하는 함수로, 매매 전략과 무관하게 종가만으로 다음을 계산한다.

- 각 날짜를 전날 종가와 비교해 **상승**(`종가 > 전날 종가`)/**하락**(`종가 < 전날 종가`)/
  **보합**(같음)으로 분류하고, 상승/하락 일수·비율을 집계한다.
- **연속 상승·연속 하락(streak)**: 방향이 이어지는 구간의 길이를 각각 모아 분포로 만든다
  (보합은 연속을 끊는다). 예: `up,up,down,up,up,up` → 연속 상승 길이 `[2, 3]`, 연속 하락
  길이 `[1]`.
- **등락률(%) 분포**: 상승일·하락일 각각의 `(종가−전날종가)/전날종가×100`을 모아 평균·
  최댓값(하락은 최솟값, 즉 가장 큰 낙폭)을 계산하고, 히스토그램용으로 **정수(1%p)
  단위로 반올림**해 값별 개수를 센다(`compute_price_stats(df, pct_round_ndigits=0)`,
  필요하면 인자로 다른 자리수를 넘길 수 있다). 연속 일수(streak) 히스토그램은 애초에
  정수(일수)라 반올림 없이 그대로 집계한다.
- 최솟값~최댓값 구간을 빈틈없이 채워서 반환하므로(값이 없는 칸은 개수 0), 히스토그램
  막대 사이에 빈 구간이 있어도 그대로 드러난다.
- **연속 일수별 평균/합계 등락률** (`_streak_length_agg`): 연속 상승·하락 구간마다 두
  가지 값을 함께 기록한다 — `평균등락률`(그 구간에 속한 날들의 일별 등락률 평균, "하루
  평균 기세")과 `총등락률`(**구간 하나 안에서** 그 며칠간의 등락률을 합친 값 — 예: 2일
  연속 상승이면 그 2일의 등락률 합. 일별 등락률을 단순 합산한 근사치가 아니라, 구간
  시작 전날 종가 대비 마지막 날 종가의 실제 등락률로 계산해 복리까지 정확히 반영한다).
  같은 길이의 구간이 여러 개 있으면 세 값을 길이별로 계산한다:
  - `1일평균`: 그 구간들의 `평균등락률`을 평균 낸 값 — "그 길이 구간 하루 동안 보통
    얼마나 움직이는지".
  - `합계평균`: 서로 다른 구간끼리 더하는 게 아니라, `1일평균`과 완전히 동일한 방식으로
    그 구간들의 `총등락률`끼리 평균 낸 값.
  - `합계최대`: 그 구간들의 `총등락률` 중 절댓값이 가장 큰 값(상승은 곧 최댓값, 하락은
    곧 최솟값 = 가장 큰 낙폭).

  이 세 값이 `/stats`의 "연속 일수별 1일 평균/합계 등락률" 그래프다: x축=연속 일수,
  왼쪽 y축=`1일평균`(항상 표시), 오른쪽 y2축=`합계평균`(기본 켜짐)·`합계최대`(기본
  꺼짐) — 두 y2 계열은 그래프 위 체크박스로 각각 켜고 끌 수 있다. 구간이 하나도 없는
  길이는 결과에서 아예 빼버린다(0으로 채우면 관측된 적 없는 길이가 관측된 것처럼
  보이기 때문).

## 로컬 데이터 파일명

메인 페이지에서 조회한 데이터는 `data/{종목코드}_{생성일자YYYYMMDD}.csv` 형식으로 저장됩니다.
파일 하나가 그 종목을 그 날 조회한 **가장 큰 범위**를 담으며, 같은 종목을 같은 날 더 짧은
기간으로 다시 조회하면 네이버를 다시 부르지 않고 이 파일을 그 기간만큼 잘라서 보여줍니다.
더 긴 과거가 필요하면 그때만 네이버에서 다시 받아 파일을 더 큰 범위로 갱신합니다. 같은
종목이라도 조회한 날짜가 다르면 별도 파일로 남으며, `/backtest`·`/daily`·`/daily2`·
`/heatmap`·`/heatmap2`·`/heatmap3`·`/heatmap4`·`/heatmap5` 페이지 모두 **종목 선택 →
생성일자 선택** 2단계 드롭다운에 더해 **기간(일)**을 독립적으로 입력받습니다(비워두면 그
파일이 커버하는 최대 범위). 요청한 종목+생성일자 조합이 로컬에 없거나 기간이 부족하면(단,
생성일자가 오늘이 아니면 더 늘릴 수 없으므로 있는 만큼만 사용) 이 페이지들도 네이버에서
자동으로 가져와 채웁니다 — 오늘이 아닌 생성일자가 로컬에 아예 없으면 그 날짜는 재현할 수
없으므로(네이버 API가 "오늘 기준 N일 전"만 지원) 오늘 기준 최신 데이터로 대체합니다.

## 참고

- 네이버 금융은 별도 API 키가 필요 없는 대신, 페이지를 스크래핑하는 방식이라
  네이버 쪽 페이지 구조가 바뀌면 코드 수정이 필요할 수 있습니다.
- 과도하게 빠른 요청을 막기 위해 `core.py`의 `sleep` 파라미터로 페이지 요청 간
  약간의 대기시간을 두고 있습니다.
- 이 앱을 실행하려는 환경에서 `finance.naver.com`으로의 아웃바운드 네트워크 접속이
  허용되어 있어야 합니다.
- 백테스트/히트맵 페이지는 네이버에 부하를 주지 않도록 로컬 CSV만 사용합니다. 새 종목/기간을
  다루려면 먼저 메인 페이지에서 한 번 조회해주세요.
